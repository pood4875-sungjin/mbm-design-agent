# 레이아웃 안 (2단계 플로우)

사용자 10-20: 「2차 단계에서는 여러 레이아웃과 디자인 템플릿이 생성되고 선택할 수 있게 해야 한다.」
**안 = 새 디자인이 아니라 편집 프리셋의 조합**이다(키비주얼 위치·크기, 글자 정렬, 브랜드색 지면, 글자색 톤). 그래서 선택해도 기존 렌더·게이트·내보내기가 그대로 돈다. 코드: `core/variants.js`, 생성 연결 `core/generate.js`, 앱 `app/app.js`.

## 흐름
1. **생성**: `generateArtifacts` 가 광고 산출물마다 기본안 + 3슬롯 후보(아래)를 순서대로 실제 렌더한다(`renderArtifact`, 렌더 평균 0.4ms · 51규격 전체 84ms).
2. **거르기**: 쓸 수 없는 후보를 버리고 등급별 안 수만큼만 남긴다(`artifact.variants[{id,label,style,hash}]`).
3. **선택**: 인스펙터 「레이아웃 안」 썸네일을 누르면 그 안의 프리셋이 `artifact.overrides.style` 로 복사된다(이전 안 키는 제거, `variantSel`, 상태 draft, 승인 예외 삭제, 로그 `variant_selected {specId, variant, label, style}`).
4. **전파**: 「이 안으로 전부」 = `restyleWith` 로 캠페인 프리셋에 전파 → 모든 광고 산출물 overrides 에서 전파 키를 걷어내고 → 안 목록을 새 기준선으로 다시 센다 → `variantSel = currentVariantIndex`. 기본안이 현재 안이면 버튼이 꺼진다.
5. **추출**: 내보내기는 기본이 선택안만. 「전체 안 포함」을 켜면 승인된 산출물의 안마다 파일이 나온다.
6. **집계**: 선택이 쌓이면 `scripts/variant-stats.mjs` 가 규격별로 센다 → 2단계 매체의 기본안을 바꿀 근거.

## 거르는 조건
1. 프리셋이 통째로 무시된 안: `edit.ignored` 「키(사유)」(예 `textAlign(규정 매체)`, `bgFill(밝은 지면 — 이음 쪽 밝기 …)`, `infoTag(규정 매체…)`). 「키.kv(…)」「키.logo(…)」는 부분 적용이라 통과.
2. 위치 프리셋이 안 선 안: `edit.place.ok === false`.
3. 겹침 교정 실패: `overlapFix.fail`.
4. 그림이 같은 안: 지문(html 에서 data URL·`data-trace` 를 뺀 해시).
5. 기본안보다 못한 안(11-05): 기본안엔 없던 겹침 교정 · 키비주얼이 빠짐.
6. **정렬-비주얼 짝(11-09)**: 글자 정렬을 바꿨는데 비주얼이 못 따라감(`alignFollows`).
7. **대비**: 메인 글자 대비 < 3(밝은 지면 안은 < 7). 기본안부터 낮은 질감 지면은 기본안보다 나빠질 때만. 태그 글자 대비 < 4.5.
8. **태그 붙일 정보 없음**: `infoTag` 안인데 그려진 태그가 0.
9. **로고 안전영역**: 틀 로고 칸·시안 틀 로고·로고 오브젝트 칸이 매체 안전영역(숫자, `logoInset` 우선) 밖(`logoInSafe`). 렌더러도 거울로 옮긴 로고 칸이 안전영역 밖이면 원자리(`textAlign.logo(…)`).

## 오토레이아웃(11-09 2b)
사용자: 「타이틀·서브텍스트가 패딩을 유지한 채로 내부 콘텐츠 3줄이면 아래로 내려가는 — 오토레이아웃처럼. 각각 이동할 수 있지만 처음엔 패딩 유지.」
- **글자 묶음 = 세로 스택(hug)**: 위·왼 패딩과 행 간격은 그대로, 메인 줄이 늘면 아래 행이 같이 내려가고 줄면 올라간다.
  - 자유 배치(flex 열)·시안 틀(ad-template)은 원래 스택이었다(실측 표 `_out/ai-track/autolayout-before.json`).
  - **틀(mold)**: 사용자 타이틀(headline)이 틀 메인 줄 수와 다르면(1~3줄, 매체 줄 수 상한 안) 메인 칸을 그 줄 수로 바꾸고 메인 아래 행(날짜·상세·태그·칩)을 같은 만큼 옮긴다(`trace.autolayout {want, lines0, dy, k, rows, over}`, 옮긴 행엔 `data-stack-dy`). afterMain 행은 원래 따라간다. 전에는 3줄 타이틀이 2줄 상자에 합쳐져 셋째 줄이 잘렸다(580·1080 「잘림」).
  - 바닥(메인 아래 그림 칸 윗변·안전영역 아래)에 닿으면 메인 글자·행간 한 단계(0.9) 축소 → 그래도 넘치면 `autolayout.over`(검수 경고).
  - 줄 수별 표가 있는 틀(bySubLines·byMainLines — 자소설)·규정 매체·세로 가운데 틀(vCenter)은 표·규정대로(스택 안 함). 타이틀을 안 적으면 지금 그림 그대로(기본안 바이트 동일).

- **인스펙터 「레이아웃 안」**: 산출물을 고르면 안 썸네일이 패널 폭 1~2열(가로로 긴 규격 1열, 규격 비율, 높이 ≤ 240)로 나오고 라벨 아래 부제가 붙는다. ⤢ 로 큰 보기 모달(「다른 시안 보기」와 같은 큰 카드). 글자 칸 프리셋에 「정보 태그」「태그 모양」이 있다. 누르면 그 안으로 바뀌고 저장된다(복원 때 `variantSel` 도 돌아온다). 캠페인 스타일이 바뀌면 안 목록이 다시 계산되고 선택은 style 동치로 다시 찾는다.
- **「이 안으로 전부」**: 지금 보는 안의 프리셋을 캠페인 전체에 전파한다.
- **내보내기**: 기본은 선택안만. 「전체 안 포함」 체크 → `매체/specId/…__안N.ext`, 루트 `전달_안내.txt` 에 규격별 「선택안 안N (라벨) — 승인은 이 안 기준」. 개별 편집값은 선택안에만 붙고 SVG 는 선택안만 나온다. 체크를 풀면 기존 구성.
- **집계**: 앱 AI 키 모달의 「캠페인 JSON 내보내기」 → `node scripts/variant-stats.mjs [mbm-campaigns.json]` → [variant-stats.md](variant-stats.md)(규격별 안 라벨 횟수, 기본안 외 %, 캠페인 일괄).

## 한계 · 후속
- 사용자가 직접 바꾼 값(예: 글자색 토글)이 어떤 안의 style 과 같으면 그 안이 선택된 것으로 보인다(style 동치 재매핑의 설계상 허용).
- 「이 안으로 전부」 뒤에 regen 이 2번 돈다(결과는 같고 낭비만).
- overrides 에 어느 안과도 안 맞는 값이 있으면 기본안이 전체 안 ZIP 에서 빠진다(드묾).
- 틀 규격(네이버 DA 등)은 위치 안이 안 서서 안이 적다. 실제 분포(ABL 누끼): 구글 580·네이버 DA = 기본안·가운데 정렬·브랜드색 지면 / 당근 = 5안 / 알바몬 PC메인(자유 band) = 기본안·키비주얼 왼쪽·가운데 정렬 / 자소설·리멤버·카카오 비즈보드 = 1안.
- 「템플릿 추가」(새 레이아웃을 틀로 더하기)는 이 플로우 밖이다. **새 템플릿은 선택 케이스를 모은 뒤 별도 구현**한다 — 선택 통계로 2단계 매체 기본안을 언제 갱신할지가 결정 사항.

## 승인과의 관계(10-20 최종 리뷰)
- 안을 고르면 그 산출물은 초안으로 돌아간다(승인·사유 삭제). 「이 안으로 전부」 뒤 그림이 바뀐 승인 산출물도 승인 해제된다(토스트에 건수). 승인된 그림은 조용히 바뀌지 않는다.
- 전달_안내.txt 는 규격마다 선택안 번호와 라벨을 적는다. 승인은 선택안 기준, 나머지 __안N 은 검토용.
