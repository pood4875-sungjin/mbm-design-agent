# 레이아웃 안 (2단계 플로우)

사용자 10-20: 「2차 단계에서는 여러 레이아웃과 디자인 템플릿이 생성되고 선택할 수 있게 해야 한다.」
**안 = 새 디자인이 아니라 편집 프리셋의 조합**이다(키비주얼 위치·크기, 글자 정렬, 브랜드색 지면, 글자색 톤). 그래서 선택해도 기존 렌더·게이트·내보내기가 그대로 돈다. 코드: `core/variants.js`, 생성 연결 `core/generate.js`, 앱 `app/app.js`.

## 흐름
1. **생성**: `generateArtifacts` 가 광고 산출물마다 후보 프리셋(아래 14개)을 순서대로 실제 렌더한다(`renderArtifact`, 렌더 평균 0.4ms · 51규격 전체 84ms).
2. **거르기**: 쓸 수 없는 후보를 버리고 등급별 안 수만큼만 남긴다(`artifact.variants[{id,label,style,hash}]`).
3. **선택**: 인스펙터 「레이아웃 안」 썸네일을 누르면 그 안의 프리셋이 `artifact.overrides.style` 로 복사된다(이전 안 키는 제거, `variantSel`, 상태 draft, 승인 예외 삭제, 로그 `variant_selected {specId, variant, label, style}`).
4. **전파**: 「이 안으로 전부」 = `restyleWith` 로 캠페인 프리셋에 전파 → 모든 광고 산출물 overrides 에서 전파 키를 걷어내고 → 안 목록을 새 기준선으로 다시 센다 → `variantSel = currentVariantIndex`. 기본안이 현재 안이면 버튼이 꺼진다.
5. **추출**: 내보내기는 기본이 선택안만. 「전체 안 포함」을 켜면 승인된 산출물의 안마다 파일이 나온다.
6. **집계**: 선택이 쌓이면 `scripts/variant-stats.mjs` 가 규격별로 센다 → 2단계 매체의 기본안을 바꿀 근거.

## 등급별 안 수 (`CANON.variants`)
| 대상 | 안 수 |
|---|---|
| 규정 매체(`fonts.required` — 자소설·리멤버·카카오) | 1 |
| 등급 B(로고·비주얼만 있는 파일 규격 — 글자·배치가 없어 안이 뜻이 없음) | 1 |
| 등급 C(자유) | 5 |
| 그 외 | 3 |

## 거르는 조건 4
1. **프리셋이 통째로 무시된 안**: `edit.ignored` 의 「키(사유)」 형태(예: `textAlign(규정 매체)`, `kvSize(매체 칸·지면 전체)`). 틀 칸 메모 「키.kv(…)」·「키.logo(…)」는 글자는 정렬되고 그림·로고 칸만 제자리라 부분 적용 — 통과(그림이 같으면 4번이 거른다).
2. **위치 프리셋이 안 선 안**: `edit.place.ok === false`(「매체 템플릿이 그림 칸을 정함」「투명 배경 규격」).
3. **겹침 교정 실패**: `overlapFix.fail`. 기본안은 면제(검수가 그대로 보고한다).
4. **그림이 같은 안**: 지문(html 에서 data URL·`data-trace` 를 뺀 해시)이 이미 있는 안과 같으면 버린다.

## 앱에서 쓰기
- **인스펙터 「레이아웃 안」**: 산출물을 고르면 안 썸네일이 나온다. 누르면 그 안으로 바뀌고 저장된다(복원 때 `variantSel` 도 돌아온다). 캠페인 스타일이 바뀌면 안 목록이 다시 계산되고 선택은 style 동치로 다시 찾는다.
- **「이 안으로 전부」**: 지금 보는 안의 프리셋을 캠페인 전체에 전파한다.
- **내보내기**: 기본은 선택안만. 「전체 안 포함」 체크 → `매체/specId/…__안N.ext`, 루트 `전달_안내.txt` 에 규격별 「선택안 안N (라벨) — 승인은 이 안 기준」. 개별 편집값은 선택안에만 붙고 SVG 는 선택안만 나온다. 체크를 풀면 기존 구성.
- **집계**: 앱 AI 키 모달의 「캠페인 JSON 내보내기」 → `node scripts/variant-stats.mjs [mbm-campaigns.json]` → [variant-stats.md](variant-stats.md)(규격별 안 라벨 횟수, 기본안 외 %, 캠페인 일괄).

## 한계 · 후속
- 사용자가 직접 바꾼 값(예: 글자색 토글)이 어떤 안의 style 과 같으면 그 안이 선택된 것으로 보인다(style 동치 재매핑의 설계상 허용).
- 「이 안으로 전부」 뒤에 regen 이 2번 돈다(결과는 같고 낭비만).
- overrides 에 어느 안과도 안 맞는 값이 있으면 기본안이 전체 안 ZIP 에서 빠진다(드묾).
- 틀 규격(네이버 DA 등)은 위치 안이 안 서서 안이 적다. 실제 분포(ABL 누끼): 구글 580·네이버 DA = 기본안·가운데 정렬·브랜드색 지면 / 당근 = 5안 / 알바몬 PC메인(자유 band) = 기본안·키비주얼 왼쪽·가운데 정렬 / 자소설·리멤버·카카오 비즈보드 = 1안.
- 「템플릿 추가」(새 레이아웃을 틀로 더하기)는 이 플로우 밖이다. **새 템플릿은 선택 케이스를 모은 뒤 별도 구현**한다 — 선택 통계로 2단계 매체 기본안을 언제 갱신할지가 결정 사항.

## 승인과의 관계(10-20 최종 리뷰)
- 안을 고르면 그 산출물은 초안으로 돌아간다(승인·사유 삭제). 「이 안으로 전부」 뒤 그림이 바뀐 승인 산출물도 승인 해제된다(토스트에 건수). 승인된 그림은 조용히 바뀌지 않는다.
- 전달_안내.txt 는 규격마다 선택안 번호와 라벨을 적는다. 승인은 선택안 기준, 나머지 __안N 은 검토용.
