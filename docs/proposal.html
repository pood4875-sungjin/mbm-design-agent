MBM 캠페인 디자인 실행 에이전트

MBM 기획 확정 후, 하나의 Campaign Context와 Design Direction으로 온·오프라인 전 채널 산출물을 자동 생성·베리에이션하고, HubSpot 등록과 인쇄용 파일까지 연결하는 대화형 에이전트.

디자이너의 전환

AS-ISeDM·Landing·배너·SNS·PPT·Poster·X-banner를 각각 반복 제작. 정보 변경 시 하나씩 찾아 수정.
→
TO-BE캠페인 디자인 시스템 하나를 설계·판단하면 AI가 전 채널로 전개. 변경은 일괄 반영.

4관점 가치

마케터 · 요청자

요청이 실행이 된다

  • 리드타임 당일화요청서→대기→시안→수정 왕복이 "브리프 입력→초안 확인"으로 압축
  • 변경 전달 1회일정·연사·장소 변경 한 번이면 전 산출물 반영 — 수정 요청 반복 소멸
  • 실행 직결eDM·Landing이 HubSpot에 바로 등록 — 발송 준비 시간 최소화
  • 채널 실험 자유규격 추가 비용 0 — 리소스 때문에 포기하던 채널 시도 가능
디자이너

제작에서 판단으로

  • 반복 제작 제거규격 전개·재배치 소멸 — 시간 60% 회수, Direction·품질 판단에 재투자
  • 수정 지옥 탈출일괄 반영 + 수정 누락 리스크 소멸
  • 직무 격상오퍼레이터 → 캠페인 디자인 시스템 설계자
  • 노하우 자산화캠페인 스타일이 프리셋으로 쌓여 조직 자산이 됨
사업 · 사업부

행사 운영이 유연해진다

  • 준비 기간 단축디자인이 병목에서 빠짐 — 기획 확정이 늦어도 실행 가능
  • 운영 리스크 감소연사 교체·장소 변경 즉시 대응, 구정보·오탈자 노출 사고 방지
  • 처리량 확대대기열 해소로 MBM 개최 빈도·동시 진행 수 확장
  • 정보 일관성전 채널이 하나의 Campaign Context를 바라봄
법인 · 전사

비용 구조와 자산이 바뀐다

  • 증원 없는 확장디자인 리소스 추가 없이 캠페인 물량을 늘리는 비용 구조
  • 소모품 → 자산1회성 디자인이 Campaign Style·프리셋·로그로 축적
  • 제작 데이터 가시화KPI 로그가 제작 비용·처리량·리드타임을 경영 지표로
  • 복제 가능한 AX 모델타 행사·타 직무·해외법인 캠페인으로 수평 확산

플로우

초록 = 사람 · 파랑 = AI · 흰색 = 시스템  |  마름모 = 판단 · 평행사변형 = 입력 · 점선 = 추후 확장

디자인 자산 검색 플로우

자연어로 물어보면 → AI가 해석 → 시스템이 검색 → 사람이 확인 → 바로 재사용

확정 결정 사항

입력 · Campaign Context

01
대화창이 유일한 입구

PPT / 워드 / 자연어 모두 허용. 파일을 던지든 말로 하든 같은 대화에서 시작.

02
산출물 선택이 스키마를 결정

공통 코어(행사명·일시·장소·CTA)는 항상, 채널별 필드는 선택한 산출물에 따라 추가 수집.

03
빈칸은 추측하지 않는다

없는 정보는 되묻는다. 최종상에선 요청자에게 직접, 파일럿에선 디자이너에게 질문 리스트로.

Design Direction

04
브랜드 제약 없음

캠페인마다 자유. 고정 브랜드 레이어를 강제하지 않는다.

05
Direction 입력 3경로

① 디자이너 제공(기본): 키비주얼+컬러+텍스트 스타일 ② AI 생성(이미지 생성 API — 추후 확장) ③ 탑재 프리셋 선택.

06
Campaign Style로 정규화

어느 경로로 들어와도 키비주얼·컬러·타이포·무드의 동일 구조로 변환 — 전개 엔진은 하나. 완료된 스타일은 프리셋 서랍에 축적.

생성 · 산출물

07
산출물 = 키비주얼 + 코드 렌더

HTML로 렌더 후 채널별 변환: eDM=이메일 호환 HTML, 배너·SNS=이미지, 포스터·X-banner=인쇄용 PDF.

08
비율 대응 규칙

키비주얼 1장을 가로·세로·정방으로 전개할 때 안전 크롭 + 색면 배경 확장. AI 아웃페인팅은 2차 확장.

수정 · 변경 전파

09
대화 지시 + 직접 편집

대화 지시 = Direction 수준 수정(전 산출물 일괄), 직접 편집 = 개별 예외 처리.

10
정보는 시스템 소유, 표현은 디자이너 소유

장소·일시·Speaker 등 Context 정보는 전파가 갱신하고, 디자이너가 만진 스타일·레이아웃은 유지. 충돌 시 목록으로 확인받는다.

실행 · 연동

11
HubSpot 연동

1차는 실행 포맷 파일 생성(이메일 호환 HTML·랜딩 패키지)까지. HubSpot API 자동 등록(eDM·Landing)은 추후 확장.

12
배너·SNS는 파일 납품까지

광고 플랫폼 등록은 범위 밖 — 디자인 직무 경계 유지.

역할 · 측정

13
2역할 + 디자이너 승인 게이트

요청자(사업/마케팅)는 브리프·정보 변경 입력, 디자이너는 Direction·승인·예외 편집. 모든 확정은 디자이너 게이트를 거친다.

14
KPI 자동 로그

산출물 수·Variation 수·수정 지시·리드타임을 도구가 기록. 이 로그가 최종상의 운영 대시보드가 된다.

확인 필요 · 리스크

  • HubSpot API 토큰 발급 — 관리자·요금제 확인 (Marketing Hub Professional 이상)
  • 예정 MBM 날짜 확정 → 개발 일정 역산
  • 직전 MBM 기획자료 샘플 확보 — Context 스키마 역설계 + 재현 테스트
  • 이메일 클라이언트 호환 HTML — 기술 리스크 최대 지점
  • 인쇄 사양 확정 — 재단 여백·해상도·인쇄소 포맷
