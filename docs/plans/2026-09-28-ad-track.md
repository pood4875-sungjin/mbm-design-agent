# Campaign Agent — 서브플랜 #4: AD 트랙 (매체 규칙 엔진)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 채용 홍보 광고 소재를 **매체별 규정에 맞춰** 일괄 생성하고, 규정 위반을 자동으로 잡아내 비디자이너 담당자가 직접 검수·추출할 수 있게 한다.

**배경 (2026-09-16 과제 개정):** 대상이 MBM 행사 → **컨시어지 팀의 고객사 채용 홍보 광고**로 바뀌었다.
규모 근거는 월 220개 소재 · 11개/일 · 소재당 수정 3회 · 협력직 디자이너 1인(월 220만 원).
11월 베타 후 컨시어지 서비스 내 채용 홍보 담당자에게 **이관**한다 — 쓰는 사람이 디자이너가 아니다.

**핵심 구조 변경:** 지금은 채널 = 렌더러 = 매체가 한 덩어리다(`banner` 채널에 Google Ads 규격 14종).
매체마다 제약이 다른 순간 이 구조가 깨진다. **매체(medium) 레이어를 새로 끼운다.**

```
트랙(track)      온라인 | 오프라인            ← 인테이크 1단계에서 갈린다
  └ 매체(medium)  사람인 · 잡코리아 · …        ← 규정의 소유자 (신설)
      └ 규격(spec) 매체 안의 소재 유형·치수     ← 기존 SPECS
          └ 채널(channel) = 렌더러 id          ← 기존 계약 유지, 손대지 않는다
```

렌더러 계약 `(context, style, spec) → html`은 그대로 둔다. 매체는 **규정의 소유자**일 뿐
그리는 방법의 소유자가 아니다 — 같은 렌더러가 매체별 제약만 달리 받는다.

**불변식 추가 (기존 4개에 이어):**
- ⑤ **매체 규정은 데이터다.** 코드에 하드코딩하지 않고 `MEDIA` 선언 한 곳에서 읽는다. 매체 추가 = 선언 1건.
- ⑥ **규정 위반은 조용히 넘기지 않는다.** 차단(block)은 승인 자체를 막고, 경고(warn)는 표시하되 사람이 넘길 수 있다.
- ⑦ **추측한 규정은 쓰지 않는다.** 출처 없는 수치는 `⚠확정 필요`로 표기하고 검사에서 제외한다.

**Tech Stack:** 기존 그대로 — 바닐라 JS(ESM), `node --test`, 빌드 도구 없음.

### Task 1: 매체 규칙 계약 + 검사기

**Files:**
- Create: `core/media.js` — `MEDIA` 선언, `mediaOf(specId)`, `rulesFor(specId)`

- Modify: `core/contract.js` — SPECS 엔트리에 `medium`, `track` 추가

- [ ] **Step 1: 규칙 스키마 정의**

검사 가능한 것만 규칙으로 둔다. 판정 불가한 항목은 규칙이 아니라 체크리스트로 내린다.

| 규칙 키 | 뜻 | 검사 방법 | 위반 등급 |
|---|---|---|---|
| `format` | 허용 파일 형식 | 내보내기 시점 | block |
| `maxBytes` | 용량 상한 | 내보낸 바이트 | block |
| `textRatioMax` | 텍스트 면적 비율 상한 | 글자 상자 면적 합 ÷ 지면 면적 | warn |
| `safeArea` | 가장자리 여백 | 요소 bbox가 침범하는지 | block |
| `minFontPx` | 최소 글자 크기 | 렌더 후 실측 | block |
| `logoMinPx` | 로고 최소 크기 | 로고 슬롯 실측 | warn |
| `maxLines` | 제목 줄 수 상한 | 렌더 후 실측 | warn |
| `requiredNotice` | 필수 고지 문구 | 지면에 존재하는지 | block |
| `bannedPattern` | 금지 표현 정규식 | 텍스트 매칭 | block |

- [ ] **Step 2: 검사기 구현 — 실측 기반**

추정하지 않는다. 렌더된 DOM에서 `getBoundingClientRect`로 실측한다(앱), 또는
테스트에서는 마크업 파싱으로 검증한다. 검사기는 순수 함수로 두고 측정값을 인자로 받는다.

- [ ] **Step 3: 채용 광고 법정 제약 조사 — 별도 확인 후 반영**

모집·채용 광고에는 차별 금지 규정이 걸린다(성별·연령·용모 등 제한 표현).
**출처를 확인하기 전에는 `bannedPattern`에 넣지 않는다.** 확인 전까지는
`⚠확정 필요` 주석만 남기고, 담당자 체크리스트 항목으로 내린다.
