2. 공통 GNB — 3가지 안

두 도구 모두 캔버스가 화면 높이 대부분을 써야 하고, 도구 고유 버튼(Generate·내보내기·승인)이 이미 상단 바에 있다. 이 조건에서 비교했다.

A. 한 줄 GNB + 도구 스위처 추천

■ 스튜디오광고 소재 ▾2025 GS에너지 공채내보내기전체 승인?●
  • 왼쪽 = 공통(로고·도구 스위처·작업 이름), 오른쪽 = 도구 액션 자리 + 공통(가이드·계정). 높이 56 한 줄.
  • 두 도구의 지금 상단 바와 구조가 같아 1차 적용 비용이 가장 작다. 캔버스 높이를 지킨다.
  • 도구가 늘어도(추진안 7) 스위처 목록만 길어진다.
  • 약점: 다른 도구가 한 번 클릭 뒤에 숨는다 → 홈 카드와 스위처의 「최근 사용」으로 보완.

B. 탭형 GNB + 도구 헤더 두 줄

■ 스튜디오엘리베이터광고 소재MBM 마케팅오프라인?●
2025 GS에너지 공채내보내기전체 승인
  • 도구 4개가 늘 보여 전환이 가장 빠르다(익숙한 상단 탭).
  • 바 두 줄(56 + 48)로 캔버스 높이가 줄어든다.
  • 도구가 6개를 넘으면 탭이 넘친다 — 「더보기」가 필요.

C. 왼쪽 레일 + 도구 헤더

광고 소재 · 2025 GS에너지 공채내보내기승인
  • 도구가 많아져도 세로로 쌓여 확장이 쉽다. 아이콘으로 상태 표시.
  • 두 도구 모두 왼쪽 패널(입력 패널·캠페인 목록)이 있어 왼쪽 열이 두 겹이 된다.
  • 1차(링크 연결)에서 각 도구 레이아웃을 크게 바꿔야 한다.

4. 단계별로 GNB를 어떻게 붙이나

단계GNB 구현도구 목록·상태홈 「최근 작업」
1차 · 통합 진입점 (10/30)도메인이 달라(vercel · GitHub Pages) 각 도구에 같은 GNB 조각(스크립트 + 스타일 한 벌)을 넣는다. 로고·스위처는 홈과 각 도구 주소로 링크. 같은 탭 이동.홈에 둔 도구 목록 파일 하나(이름·주소·상태·담당)를 홈 카드와 스위처가 같이 읽는다숨김(도구마다 저장 위치가 달라 모을 수 없음)
2차 · 같은 서버 · UI 통일 (11/13)한 서버 아래 경로(/elevator · /ad …)로 모이고 GNB 는 공통 셸 하나. 폰트·컬러·간격·버튼·로딩/오류/완료 상태 통일같은 파일도구별 저장 기록을 모아 표시
3차 · 레포 통합 (12월)공통 레포의 공통 UI 패키지관리자 화면에서 관리로그인·제작 이력 저장 방식 정한 뒤(개발자 협의)
