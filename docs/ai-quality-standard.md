# AI 생성 품질 기준 (초안 · 2026-11-19)

> 상태: **초안** — 사용자가 축·점수 문장·목표선을 고친 뒤 확정한다. 확정 전에는 코드·게이트를 바꾸지 않는다.
> 관련: [ai-design-flow.md](ai-design-flow.md)(AI 트랙 흐름) · [ai-rule-layers.md](ai-rule-layers.md)(규칙 층 L0~L3) · [freedesign-rules.md](freedesign-rules.md)(AI 최소 규칙)

## 0. 왜 필요한가
- 지금 AI 안은 **게이트(통과/반려)** 로만 걸러진다. 통과한 안끼리 「어느 게 더 잘 만들었나」를 재는 자가 없다.
- 검증 루프(11-09~10)의 「눈 점수」는 피그마 시안 = 4 로 놓고 사람이 1~5 를 매겼지만, 무엇을 보고 몇 점인지 적어 둔 문장이 없어 회차마다 기준이 흔들렸다(3.59 → 3.85 가 진짜 좋아진 건지 말하기 어렵다).
- 셀렉 루프 평가 36건(첫 18안: 좋음 2 · 보통 4 · 안 됨 12)도 「왜 안 됨인지」가 남지 않아 프롬프트를 어디부터 고칠지 모른다.

이 문서는 **같은 자로 재고, 바꿀 때마다 전과 견주는** 기준을 정한다.

## 1. 세 단계
| 단계 | 묻는 것 | 결과 | 누가 |
|---|---|---|---|
| ① 출고 가능 | 내보내도 사고가 안 나나 | 예 / 아니오 + 사유 규칙 id | 게이트(자동) |
| ② 품질 점수 | 디자이너 시안만큼 잘 만들었나 | 다섯 축 × 1~5 점 + 총점 | 사람(눈) + 자동 보조값 |
| ③ 세트 | 3안이 고를 만한 묶음인가 | 다양성 · 3안 출고 가능 수 | 자동 + 사람 |

①을 못 넘은 안은 ②를 매기지 않는다(점수 = 0, 사유만 센다).

### 역할 나눔 (사용자 11-19 결정)
> 「나는 기본적인 지켜야 할 가이드(폰트 크기·위치 그런 거) 말고 비주얼적인 부분이나 디자인적인 피드백을 줄 거야. 그게 소재 가이드에 통과되는지는 너가 알아서 판단해 줘야 해」

| 사용자 | Claude |
|---|---|
| 비주얼·디자인 피드백만 — 느낌·조화·키비주얼 쓰임·완성도·「이건 디자이너 같다/아니다」 | 가이드 통과 판단 전부 — 매체 규정(글자 수·크기·안전영역·로고), 공통 원칙(대비·가림·연도·날짜), AI 전용 규칙 |
| 자유 문장 또는 좋음/보통/별로 | 피드백을 다섯 축 점수·사유로 옮겨 적기 |
| 어긋난 안에서 「이게 맞다」 판단 | 피드백대로 고친 안이 가이드를 깨면 **가이드가 이긴다** — 깨지 않는 다른 방법을 찾고, 없으면 그렇다고 알린다 |

- 사용자에게 보이는 비교 시트에는 **가이드를 통과한 안만** 올린다. 반려된 안은 사유 집계로만 남긴다.
- 사용자 피드백이 가이드 수치(글자 크기·위치·여백)를 직접 가리키면(예: 「글자 더 크게」), Claude 가 가이드 범위 안인지 먼저 보고 범위 밖이면 그 이유와 범위 안의 대안을 같이 낸다.
- 다섯 축 중 사용자 피드백의 주 대상은 **키비주얼 활용 · 색·톤 · 완성도**, 그리고 위계·여백의 「보기 좋음」 쪽이다. 위계·여백의 숫자 하한·상한은 Claude(게이트) 몫.

## 2. ① 출고 가능 — 지금 게이트를 그대로
지금 `server/freedesign.js gateIssues` 가 보는 것:
- 매체 규정(L0): 글자 수·크기 범위·안전영역·잘림·용량 등 lint block
- 공통 원칙(L1): 대비(`CANON.contrastMin` 24px↑ 2.2 · 그 밖 3), 연도 한 번·라벨 두 번 금지·날짜 필수, 주인공 가림(15%)·로고 가림(5%), 로고 묻힘, 로고 비중(메인 px × 2.4), 작은 글자(√면적 비례 하한)
- AI 전용(L3): 양의 자간·장평 금지, 정보 블록 한 규칙, 간격 하한/상한, 글자–키비주얼·로고 겹침/거리, 장식 겹침, 카드 위 글자

**바꿀 것은 하나**: 사유 문장 앞에 규칙 id 를 붙여(`{ rule, layer, msg }`) 반려 사유를 셀 수 있게 한다([ai-rule-layers.md](ai-rule-layers.md) 5절 4단계). 그래야 「반려의 몇 %가 간격 때문인지」가 나온다.

## 3. ② 품질 점수 — 다섯 축
**기준점**: 같은 KV·같은 규격의 피그마 디자이너 시안 = **4점**. 5점은 「디자이너 시안보다 낫다 / 그대로 실무에 쓰고 싶다」.
점수는 축마다 정수로 매기고, 2점 이하에는 한 줄 사유를 반드시 쓴다(→ 고칠 곳 목록이 된다).

### 3-1. 위계 (타이포)
읽는 순서가 「메인 → (서브) → 정보 블록」으로 한눈에 서는가.

| 점수 | 기준 |
|---|---|
| 5 | 크기·굵기·색 대비가 분명하고, 메인이 한 덩어리로 강하게 읽힌다. 정보 블록은 작지만 또렷하다 |
| 4 | 디자이너 시안 수준. 순서가 바로 읽히고 어색한 줄바꿈이 없다 |
| 3 | 순서는 읽히지만 메인과 서브(또는 정보)의 크기 차이가 약하거나, 줄바꿈 하나가 어색하다 |
| 2 | 메인이 묻힌다 — 서브·정보가 메인만큼 크거나, 메인이 너무 작아 지면이 빈다 |
| 1 | 무엇을 먼저 읽을지 모르겠다 |

자동 보조값: 서브/메인 px 비, 정보/메인 px 비, 메인 px ÷ √면적(규격 분포 `core/template-norms.js` 의 몇 분위인지), 메인 줄 수.

### 3-2. 키비주얼 활용
그림의 주인공이 살아 있고, 그림이 지면의 주연인가.

| 점수 | 기준 |
|---|---|
| 5 | 그림 크기·위치가 구성의 중심이고, 누끼는 누끼답게(떠 있지 않게), 사진은 끊김 없이 쓰였다 |
| 4 | 디자이너 시안 수준. 주인공이 잘리지 않고 충분히 크다 |
| 3 | 그림이 작거나 구석에 몰려 「붙여 놓은」 느낌. 주인공은 온전하다 |
| 2 | 주인공 일부가 글자·장식에 가리거나 어색하게 잘린다 / 늘어나 보인다 / 흐리다 |
| 1 | 그림을 거의 못 쓴다(배경 무늬 수준이거나 알아볼 수 없다) |

자동 보조값: KV 면적 %(`design-score.py` 와 같은 재는 법), 주인공 상자 가림 %, 원본 대비 확대 배율(흐림), 녹임/끊긴 변 유무.

### 3-3. 여백·정렬
쏠림 없이 숨 쉬는가. 정렬선이 지켜지는가.

| 점수 | 기준 |
|---|---|
| 5 | 여백이 의도적으로 보이고(긴장감 또는 여유), 모든 요소가 2~3개의 정렬선에 붙는다 |
| 4 | 디자이너 시안 수준. 쏠림·빈 띠가 없다 |
| 3 | 한쪽이 약간 비거나 붙지만 전체는 정돈돼 보인다 |
| 2 | 큰 빈 띠, 가장자리에 붙은 글자, 정렬선이 3개 넘게 흩어짐 중 하나가 눈에 띈다 |
| 1 | 요소가 흩어져 있다 |

자동 보조값: 왼쪽·위 여백(분포 몇 분위), 빈 칸 비율(룰 트랙 emptyFix 와 같은 재는 법), 서로 다른 왼쪽 x 개수, 간격 상·하한 대비 위치.

### 3-4. 색·톤
지면·그림·글자 색이 한 벌로 보이는가. 브랜드가 느껴지는가.

| 점수 | 기준 |
|---|---|
| 5 | 그림 색에서 뽑은 지면·강조가 자연스럽게 이어지고, 브랜드색이 포인트로 살아 있다 |
| 4 | 디자이너 시안 수준. 이음매·탁함이 없다 |
| 3 | 조화는 되지만 밋밋하다(회색조·단색 지면에 강조 없음) |
| 2 | 지면이 그림보다 탁하거나(11-17 칙칙함), 그림 변과 지면 사이 이음매가 보이거나, 색이 3개 넘게 다툰다 |
| 1 | 색이 서로 부딪혀 그림이 망가져 보인다 |

자동 보조값: 지면 ↔ 그림 변 색 거리(`CANON.aiFieldEdgeMax` 와 같은 재는 법), 지면 채도·밝기, 쓴 색 수, 브랜드 주색 쓰임 여부.

### 3-5. 완성도 (AI 티)
사람 디자이너가 만든 것처럼 보이는가.

| 점수 | 기준 |
|---|---|
| 5 | 장식이 있으면 의미가 있고(그림·브랜드에서 나옴), 마감이 깔끔하다 |
| 4 | 디자이너 시안 수준. 「AI 가 만들었다」고 느껴지는 곳이 없다 |
| 3 | 흔한 장식(빛 번짐·의미 없는 원·칩)이 하나 있지만 거슬리지 않는다 |
| 2 | 장식이 글자·그림과 겹치거나, 그라데이션·글로우가 과하다 / 템플릿을 채운 느낌 |
| 1 | 한눈에 AI 생성물 |

자동 보조값: 장식 요소 수·겹침(`typoaudit overlapAudit`), 글로우·그림자·그라데이션 글자 개수.

### 3-6. 총점
- 총점 = 다섯 축 평균(소수 둘째 자리). 축마다 무게는 같다(초안 — 아래 열린 결정 2).
- 한 축이라도 **2 이하**면 「손봐야 씀」 표시 — 평균이 높아도 그 안은 추천 첫 칸에 두지 않는다.

## 4. ③ 세트 — 3안 묶음
| 항목 | 기준 |
|---|---|
| 출고 가능 수 | 3안 모두 ① 통과 |
| 구성 다양성 | 3안의 구성(전면 비주얼·그래픽 모티프·타이포 주도·대각/곡선·카드/프레임·가운데 축)이 모두 다르다 |
| 고를 만함 | 3안 중 최고점 ≥ 4, 최저점 ≥ 3 |
| 시간 | 첫 카드 · 3안 · 즉시 수정 · AI 수정 시간을 같이 적는다(기준선 대비 느려지면 표시) |

## 6. 재는 절차
1. `node scripts/freedesign-ai-loop.mjs --round N` 으로 묶음 생성 → 안마다 PNG + 같은 KV 피그마 시안 나란히 시트.
2. 자동: ① 게이트 결과(사유 규칙 id) · ② 축별 보조값 · ③ 다양성·시간 → `scores.json`.
3. 사람: 가이드를 통과한 안만 시트로 보고 **비주얼·디자인 피드백**(자유 문장 또는 좋음/보통/별로)을 남긴다. Claude 가 그 피드백을 축별 점수·사유로 옮겨 같은 `scores.json` 에 기록하고, 옮긴 결과를 사용자에게 한 번 보여 맞는지 확인한다.
4. 요약 표: 회차별 출고 가능률 · 축별 평균 · 총점 평균 · 「손봐야 씀」 수 · 반려 사유 상위 5 · 3안 세트 기준 충족 수.
5. 가장 낮은 축 하나를 골라 프롬프트·자동 고침·규칙을 바꾸고 같은 묶음으로 다시 잰다. 한 회차에 한 축만 바꾼다(무엇이 효과였는지 가리기 위해).

## 7. 목표선 (초안)
| 지표 | 기준선 | 1차 목표 | 근거 |
|---|---|---|---|
| 출고 가능률(안) | 다시 잼 | ≥ 90% | 11-10 r5 노출 안 중 추천 42/48 = 88% |
| 3안 세트 충족(작업) | 다시 잼 | ≥ 13/16 | 11-10 「3안 보장」 목표 |
| 총점 평균(출고 가능 안) | 다시 잼 | ≥ 3.8 | 11-10 눈 점수 ≈ 3.85(기준 문장 없이 매긴 값) |
| 「손봐야 씀」 비율 | 다시 잼 | ≤ 15% | — |
| 첫 카드 / 3안 시간 | 다시 잼 | ≤ 90s / ≤ 180s | 11-10 r3 66s / 134s(정상 시간대) |

40%·80% 실무 KPI 처럼, 목표선은 기준선을 잰 뒤 다시 맞춘다.

## 8. 쓰임 — 기준이 생기면 바뀌는 것
- **추천 순서**: 게이트 통과 안끼리 자동 보조값으로 미리 점수를 매겨 높은 안을 첫 칸에(사람 점수와 맞는지는 회차마다 확인).
- **프롬프트 고침 근거**: 「2점 이하 사유」 상위가 곧 다음 회차에 고칠 곳.
- **규칙 승격**: 4점 이상 안에서 자주 나오는 구성 → 룰 트랙 시안 슬롯 후보(L2), 반려가 몰리는데 사람이 좋다고 고른 L3 규칙 → 완화 후보([ai-rule-layers.md](ai-rule-layers.md) 2절 되먹임).
- **주간 보고**: 업무 대체율·제작 시간 옆에 「AI 안 품질 총점 · 출고 가능률」을 같은 표로.

## 9. 열린 결정
