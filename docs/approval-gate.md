# 승인 게이트 — 무엇이 승인되고 무엇이 막히나 (2026-10-20)

한 줄: **규정 위반은 막고, 사람이 봐야 할 것은 사유를 적게 하고, 기준이 명확한 것만 묶음 승인한다.** 확신 없으면 내보내지 않고 표시한다(광고는 틀린 걸 내보내는 비용이 더 크다).
코드는 `core/gate.js` `approvalGate({grade, lint, design, samples})`, 규칙 장부 `approval-gate`·`ship-rules-grade-a`(r68). 출고 체크리스트는 [ship-checklist.md](ship-checklist.md).

## 상태 5개
| 상태 | 화면 배지 | 뜻 | 승인 방법 | 전달(ZIP) |
|---|---|---|---|---|
| `blocked` | 차단 | 규격 검사(lint) 차단 — 매체 규정 위반(글자 수·크기·금지색·로고 개수·전달물 최소 폭 등) | 불가. 고친 뒤 다시 | 안 나감 · 승인·내보내기 거부 토스트 |
| `pending` | 검사 중 | 규격 검사 전, 또는 디자인 검수(겹침·로고 가림 등 브라우저 실측) 전 | 검사가 끝나면 다른 상태로 | 안 나감 |
| `review` | 검수 필요 | 규정은 통과했지만 사람이 볼 것이 있음(REVIEW_CODES 경고 · 샘플 문구) | 인스펙터 「이 소재 승인」 + **사유 입력 필수** | 승인하면 나감 |
| `ready` | 승인 가능 | 등급 A·B 이고 위 항목이 하나도 없음 | 「전체 승인」(검사 통과분만 모달) 또는 개별 | 승인하면 나감 |
| `draft` | 초안 | 등급 C(자유 배치) 또는 등급 없음 — 디자이너 수정 전제 | 개별 승인만, 사유 입력 | 승인하면 나감 |

판정 순서: lint 차단 → blocked / lint 없음 → pending / REVIEW_CODES 경고·샘플 문구 → 사유 / 등급 C·없음 → draft / 사유 있음 → review / 없음 → ready.

## 「검수 필요」로 올리는 경고 (REVIEW_CODES)
| 코드 | 뜻 |
|---|---|
| `text-over-subject` | 글자가 키비주얼 주인공 위에 얹힘 |
| `logo-covered` | 로고가 가려짐 |
| `text-clipped` | 글자가 잘림 |
| `low-res` · `low-res-logo` | 키비주얼·로고가 흐릿함(저해상도). info 라도 유지 — 흐린 키비주얼은 출고 불가 사유 |
| `chip-overflow` | 칩이 칸을 넘침 |
| `design-failed` | 디자인 검수 자체가 실패 → 사람이 본다 |
| (샘플 문구) | `data-sample` 자리표시(0/00 날짜·「모집 직무를 입력하세요」)가 남음 |

**일부러 제외한 취향 경고**: `hard-cut`(끊김) · `short-melt`(짧은 녹임) · `band-seam`(띠 이음매) · `empty-band`(빈 띠) · `busy-under-text`(글자 밑 복잡). 이들은 「더 낫게 만들 수 있다」는 미적 판단이지 출고 사고가 아니다. 넣으면 대부분의 소재가 review 로 쏠려 「승인 가능」 묶음이 의미를 잃는다. 읽는 사람이 눈으로 보는 시안 단계에서 다룬다.

## 등급 (`core/media/_extract.json` grades)
| 등급 | 개수 | 뜻 | 게이트 |
|---|---|---|---|
| A | 38 | 매체 규정·틀이 데이터로 묶여 기준이 명확, 디자인 난이도 낮음 | ready 가능 |
| B | 12 | 규정은 있으나 변수 큼(로고·프로필 6규격 등) | ready 가능 |
| C | 1 (`daangn-native-feed-image`) | 자유 배치 | 늘 draft |

**자소설 11 · 리멤버 8 = 전부 A** — 11월 「100% 대체」 대상(10-19 회의). 두 매체는 규정 전 항목을 검사 코드로 묶었다(`bg-banned` · `logo-forbidden`/`logo-count` · `text-colors-uniform` · `asset-min`/`format`).

## 사유 승인 = 사례 기록의 입력
review·draft 를 사유와 함께 승인하면 `a.gateOverride = {state, reasons, reason, at}` 로 저장된다(재열기 복원, 편집하면 사유 삭제). 이 기록은 P1 「사례 기록」의 입력이다 — 어떤 경고를 사람이 「괜찮다」고 넘겼는지가 쌓이면 문턱값·제외 목록을 근거 있게 조정할 수 있다.

## 앱에서 쓰는 법
프레임 위 **게이트 배지**(차단 / 검사 중 / 검수 필요 / 승인 가능 / 초안)가 상태를 보여 준다(보드 카드의 다른 배지는 숨기는 규칙에서 게이트 배지만 예외). 상단 **「전체 승인」**은 `승인 가능` 인 것만 모달에 모아 한 번에 승인하고, 차단·검수 필요·초안은 건드리지 않는다. 인스펙터의 **「이 소재 승인 / 승인 취소」**는 review·draft 면 사유 입력란이 나오고, 차단이면 거부한다. **ZIP 내보내기**는 승인된 소재만(전달물 포함) 담고 「승인 N장 / 전체 M장 · 미승인 K장 제외」를 표시한다.

**기타**

- 미업로드 전달물이 lint pass 로 보여 `lintHtml` 문구가 어색함.
- 리멤버 글자색 「검정/흰색 택1」을 lint 가 메인=검정·서브=흰색으로만 검사 → 흰 메인이 차단될 수 있음. `textColors` 에 택1 표현 필요.
