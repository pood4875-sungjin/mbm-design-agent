# 2026-11-02: 내 캠페인 저장을 localStorage 에서 IndexedDB 로

**상태: worktree 브랜치 커밋(푸시 안 함).** 렌더 결과는 그대로, 저장 경로만 바뀐다.

## 1. 사용자 요청
- 「이거 데이터 5개 이상 안되던데? 저장이 - 서브에이전트로 이거 늘려줘 최대로..」
- 「왜 막아놧는지도 이유 말해줘」

## 2. 왜 막혀 있었나
**개수 제한은 코드에 없었다.** 막은 것은 브라우저의 localStorage 용량이다.

- 캠페인 전부를 키 하나(`mbm-campaigns`)에 JSON 으로 통째로 썼다(수정 전 `app/app.js:400-401` `loadStore`·`saveStore`). 키비주얼·로고가 data URL 로 그 안에 들어 있고, `keyVisual` 과 원본 `kvOrig`, `logo` 와 `logoOrig` 처럼 같은 그림이 두 번 들어가기도 한다.
- Chrome 실측 한도는 약 5.00MB(글자 수). 이 주소의 다른 저장 값(hub 문서, 첨부 폰트)과 같이 쓴다.
- 재현(`scripts/campstore-e2e.mjs` 0단계, 옛 쓰기와 같은 방식): base64 1.00MB 그림 ×2 캠페인은 **2개**, 0.50MB ×2 는 **5개**에서 `QuotaExceededError`. 사용자가 본 5개는 이 범위다. 사용자 브라우저의 실제 값을 읽어 본 것은 아니다.
- 일부러 정한 제품 정책이 아니었다. 8월 첫 구현의 임시 처리다: `docs/plans/2026-08-10-front-door-plus.md:20` 「localStorage `mbm-campaigns` 축적(쿼터 초과 시 메타만)」, 커밋 `4aab667`(2026-08-10), 실패 알림은 `a00fec7`(같은 날).
- 나쁜 동작이 같이 있었다(수정 전 `app/app.js:3628-3631`): 넘치면 **키비주얼을 빼고 다시 저장**해, 들어가면 사용자에게 알리지 않고 그림이 사라졌다. 그래도 넘치면 2.4초 토스트 하나만 보이고 새 캠페인은 남지 않았다.

## 3. 바꾼 것
| 파일 | 내용 |
|---|---|
| `core/campstore.js`(새) | 그림 떼기·끼우기(`dehydrate`·`rehydrate`), 저장소 본체(`createCampStore`), 이전, localStorage 대체 장치. DOM 없음 |
| `app/campdb.js`(새) | IndexedDB 장치(`campaigns` + `assets` 두 저장소, 한 트랜잭션), 못 쓰면 localStorage 로 내려감, 4초 무응답도 내려감 |
| `app/app.js` | 저장·목록·열기·썸네일·JSON 내보내기를 저장소로, 저장 실패 창, 닫기 전 경고. 키비주얼 몰래 빼기 삭제 |
| `app/index.html` | 작업공간 메뉴가 저장소를 읽음 |
| `test/campstore.test.js`(새) | 22건(메모리 장치) |
| `scripts/campstore-e2e.mjs`(새) | 헤드리스 Chrome 실제 시험 |

- **구조**: 기록(그림 뺀 JSON, 1건 약 26KB)은 메모리에 두고 목록이 곧바로 읽는다. 64KB 넘는 data URL 은 내용 해시를 id 로 따로 둔다. 같은 그림은 한 번만 저장한다.
- **자동 저장**: 이미 있는 그림은 값을 다시 쓰지 않는다(`getKey` 로 확인).
- **이전**: 시작할 때 옛 키를 한 건씩 옮기고, 다시 읽어 전부 있음을 확인한 뒤에만 옛 키를 지운다. 같은 id 는 `savedAt` 이 새로운 쪽을 남긴다. 값이 망가졌으면 지우지 않고 알린다. 공간이 모자라면 원본을 두고 목록에는 보여 주며 다음 실행 때 다시 옮긴다.
- **저장 실패**: 지우지 않는다. 실패 창(이어지는 실패는 토스트)과 「이 캠페인 JSON 내려받기」를 보여 주고, 그림은 메모리에 남겨 다음 저장 때 같이 쓴다. 저장 중이거나 실패 상태면 탭을 닫기 전에 묻는다.
- **폴더**(`mbm-folders`)는 작아서 localStorage 그대로. 옛 폴더 배정은 유지된다.
- 새 라이브러리 없음.

**안 돌린 것**: 진짜 IndexedDB 쿼터 초과(`Storage.overrideQuotaForOrigin` 이 이 Chrome 에서 먹지 않아 트랜잭션 abort + `QuotaExceededError` 로 흉내), Safari·Firefox, 실제 사생활 보호 창, 공개 주소(GitHub Pages), 「캠페인 JSON 내보내기」 버튼 클릭(함수는 단위 테스트만), 두 탭 동시 사용.

## 5. 남은 것
- **이름이 같으면 덮어쓴다(기존 동작, 안 고침)**: 캠페인 id 가 이름에서 나온다(`slug(campaignName)`). 같은 고객사·같은 직무로 새로 만들면 새 줄이 생기지 않고 앞 캠페인을 덮는다. 개수 한도와는 별개로 「안 늘어나는」 원인이 될 수 있다. 사용자 확인 필요.
- **캠페인 삭제 UI 가 없다.** 쌓이기만 한다.
- 기기·브라우저 간 공유 안 됨. 브라우저 데이터를 지우면 사라진다. JSON 내보내기는 있지만 가져오기는 없다.
- 허용량은 브라우저마다 다르다. Safari 는 사이트를 7일 안 쓰면 지울 수 있다(`navigator.storage.persist()` 로 요청은 한다).
- 첨부 폰트(`FONTS_LS`, 건당 2.4MB 까지)와 `hub/` 문서는 여전히 localStorage 다.
- 작업공간 메뉴는 묶음마다 8개까지 보이고 나머지는 「N개 더 — 홈에서 보기」다(기존 표시). 홈 목록은 전부 보인다.
