# 2026-10-22 — A/B 비교 환경: 규칙 렌더러(A) vs AI 디자인(B)

## 왜
지금 에이전트는 매체 규칙·템플릿으로만 소재를 그린다(A). Claude 가 키비주얼·로고·문구·고객사 요구·브랜드 색·매체 규격을 보고 **디자인 구성 자체를 판단**하는 방식(B)이 더 나은지, 같은 입력으로 나란히 놓고 재 보기 위한 환경을 만들었다. 공개 배포(main)는 건드리지 않고 별도 브랜치·폴더에서.

## 현황 점검(1단계)
- LLM 을 쓰는 곳은 `app/agent.js agentTurn`(브리프 해석) 하나뿐 — 브라우저가 `app/config.local.js`/localStorage 의 키로 api.anthropic.com 을 직접 부르고, 키가 없으면 규칙 파서 `scriptedTurn` 으로 폴백. 디자인 판단·검수(`core/gate.js`·`core/adcheck.js`·`core/lint.js`)는 API 를 안 쓴다.
- `app/config.local.js` 는 자리표시(`sk-ant-...`)만 있고 실제 키는 없음 → B 트랙은 **키를 서버에 넣어야** 돈다.

## 하이브리드(A+AI) — 비용 토론 뒤 추가(같은 날 오후)
사용자 관찰: 「비주얼에 어울리게 판단·키비주얼 crop·배치는 AI 가 나았고, 타이포는 규칙이 나았다」 + 「규격마다 85원은 많다(20종 = 1,700원/캠페인)」 → **AI 는 그림 판단만(캠페인당 1회), 그리기는 규칙**으로 갈래 추가. 장식 그래픽은 안 넣음(퀄 들쭉날쭉), 배경 생성(아웃페인팅)은 보류.
- `core/trackb/analyze.js`: 판단 스키마(유형·주인공·보존 요소·잘라도 되는 변·분위기 + 모양 묶음 5개(wide·tall·square·tower·strip)마다 crop·kvPlace·kvSize·textAlign·textAnchor·bgFill·bgGrad·scrim — 전부 기존 프리셋 선택지) · 검증(픽셀→비율, crop 이 주인공·보존 요소 자르면 넓힘, 선택지 밖 auto, custom 색 금지) · `presetPatch`·`kvMetaWithAi`·`resolveAiStyle`.
- `server/design.js analyzeKv` + `POST /api/analyze`(Sonnet 5.5 medium 기본). **첫 시도 400** 「compiled grammar is too large」 — 모양 묶음 5개를 객체로 복제한 스키마가 너무 컸다 → 배열(항목에 shape 꼬리표) 하나로 줄여 통과.
- `app/hybrid.js`: 모양 묶음마다 crop 사본(캔버스) + 측정 + 프리셋 조각 → `renderArtifact`. 비교 화면 가운데 「A+AI」 열 + 「A+AI 그림 판단」 버튼 + 판단 JSON 저장/불러오기. 본 앱 인스펙터 「AI 그림 판단」(광고 규격 전부에 `overrides.style.aiShape`+프리셋, crop 사본은 캠페인 `c.ai.groups` 모양별 5개 — `generate.js`·`adEffStyle`·`editor.js effStyleOf` 가 `resolveAiStyle` 로 해석) · 「AI 판단 해제」.
- `scripts/ab-run.mjs` 에 C(PIL crop + `case-rgba.py` 측정) · 테스트 `test/hybrid.test.js` 4건(전체 **551**).
