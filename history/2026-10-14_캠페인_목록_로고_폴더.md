# 2026-10-14 — 내 캠페인 목록: 로고 썸네일 · 폴더

사용자 요청: 「리스트 썸네일은 기업 로고가 나오게 해주고, 폴더링 할 수 있도록 기능을 고도화해줘.」
홈 왼쪽 「내 캠페인」 목록과 위 막대 「내 캠페인 ⌄」 메뉴만 고쳤습니다. 광고 그림(렌더러·규칙)은 바뀌지 않습니다.

## 1. 로고 썸네일
- 캠페인에 로고(`style.logo`)가 있으면 40px 칸 안에 로고를 **contain(잘리지 않게)** 으로, 사방 10% 여백을 두고 앉힙니다. 없으면 예전처럼 브랜드색 칸 + 이름 두 글자.
- 칸 바탕은 로고 톤이 정합니다(테마와 무관).
  - 흰·밝은 로고(`logoMeta.tone` = light, 없으면 `logoTone`, 그것도 없으면 썸네일에서 직접 잼) → **어두운 칸** `--tile-dark`
  - 그 밖의 로고 → **밝은 칸** `--tile-light` + 얇은 테두리 `--tile-line`
- 빠르게: 로고가 처음 보일 때 **96px PNG 썸네일**을 한 번 만들어 캠페인 기록에 `logoThumb {sig, src, tile}` 로 둡니다. 목록은 이 작은 그림만 읽습니다(예: 원본 로고 9.5KB → 썸네일 4.7KB, 큰 로고일수록 차이가 큼).
  - `sig` = 로고 데이터의 길이 + 두 구간 글자. 로고를 갈면 서명이 달라져 다음 홈 진입 때 다시 만듭니다.
  - 캠페인을 다시 저장할 때(`saveCampaignToStore`) 로고가 그대로면 썸네일을 이어 씁니다(추가 2줄).
- `alt` = 「(고객사 또는 캠페인 이름) 로고」.

## 2. 폴더
| 기능 | 마우스 | 키보드 |
|---|---|---|
| 새 폴더 | 「내 캠페인」 옆 **＋ 새 폴더** | 같은 버튼 Tab → Enter, 이름 쓰고 Enter |
| 접기·펴기(상태 기억) | 폴더 머리 클릭 | 머리에서 Enter / Space (`aria-expanded`) |
| 캠페인 옮기기 | 행을 폴더 위로 **끌어 놓기**(놓을 자리 파란 테두리) | 행의 **폴더로 이동** 버튼 → 라디오(↑↓) → Enter. 새 폴더를 만들며 옮기기도 됨 |
| 이름 바꾸기 | 머리의 **⋯** → 이름 고치고 저장 | ⋯ 버튼 Enter → 이름(전체 선택된 채로 열림) → Enter |
| 순서 바꾸기 | 폴더 머리를 다른 폴더 위로 끌어 놓기(「폴더 없음」에 놓으면 맨 끝) | 머리에서 **Alt+↑/↓**, 또는 ⋯ → 위로/아래로 |
| 삭제 | ⋯ → 폴더 삭제 → 확인 창 | 확인 창은 「취소」에 포커스(실수로 지우지 않게), Esc 로 닫힘 |

- 삭제하면 안의 캠페인은 「폴더 없음」으로 갑니다. 캠페인은 지워지지 않습니다. `confirm()` 대신 앱의 모달을 씁니다.
- 이름 검사: 빈 이름·같은 이름·「폴더 없음」은 막고 칸 아래에 빨간 한 줄(`aria-invalid`). 칸을 떠날 때 검사합니다.
- 빈 폴더에는 「비어 있어요 — 캠페인을 여기로 끌어 놓거나 행의 폴더 버튼으로 옮기세요.」
- 폴더를 하나도 안 만든 사람에게는 **예전과 똑같은 한 줄 목록**이 보입니다(묶음 머리 없음).
- 폴더 이동 버튼은 마우스를 올리거나 포커스가 있을 때 상태 배지 자리에 뜹니다 — 이름 폭을 빼앗지 않게. 터치 기기(hover 없음)는 늘 보입니다.
- **검색**은 폴더를 가로질러 거르고, 결과마다 폴더 이름을 붙입니다. 폴더 이름으로 검색해도 그 안의 캠페인이 나옵니다(예: 「채용」 → 「채용 고객사」 폴더의 2개). 채용 캠페인은 이름이 없어 예전엔 검색이 안 됐는데, 이제 고객사·직무로도 찾습니다.
- **위 막대 「내 캠페인 ⌄」**: 폴더별 머리(「채용 고객사 · 2」)로 묶고, 로고 썸네일이 있으면 색 점 대신 로고. 묶음마다 8개까지, 넘치면 「… N개 더 — 홈에서 보기」. 고르면 홈 목록의 같은 행(`data-id`)을 엽니다(예전엔 이름 글자 비교).

## 3. 저장과 기존 데이터
- 캠페인: 그대로 `localStorage['mbm-campaigns']`. 캠페인 기록에 더해지는 것은 `logoThumb` 하나뿐.
- 폴더: 새 키 `localStorage['mbm-folders']` = `{ v: 1, folders: [{id, name, open}], assign: {캠페인id: 폴더id}, noneOpen }`.
  - 폴더 배정을 캠페인 기록에 두지 않은 이유: 캠페인은 저장할 때마다 스냅샷을 새로 써서, 거기 둔 폴더 정보는 다른 코드가 저장할 때 사라진다.
- 이전(migration): `core/folders.js migrateFolders` — 키가 없거나 JSON 이 깨졌으면 빈 폴더로 읽어 **모든 캠페인이 「폴더 없음」에 그대로**. 중복 폴더 id·지워진 폴더를 가리키는 배정·없어진 캠페인 배정은 버립니다. 앱에서 키 삭제·깨진 JSON 두 경우 모두 한 줄 목록 4개 그대로, 캠페인 기록에 `folderId` 같은 필드가 생기지 않음을 확인.

## 4. 바꾼 파일
- `core/folders.js`(새 파일) — 순수 연산: 이전·만들기·이름·삭제·순서·옮기기·접기·검색·묶기·로고 서명·타일 톤·contain 상자
- `app/app.js` — `renderSidebar` 를 폴더 묶음·검색·썸네일로 바꿈, 폴더 모달 4종(새 폴더·폴더로 이동·폴더 관리·삭제 확인), Esc 로 모달 닫기, `saveCampaignToStore` 썸네일 이어 쓰기 2줄. 인스펙터·작업 화면·내보내기는 손대지 않음
- `app/index.html` — 목록 CSS(클래스 접두어 `cf-` — 아트보드 `.fbody` 와 이름이 겹쳐 흰 카드가 생기던 것을 피함), 타일 토큰 `--tile-light/dark/line`(다크 모드 값 따로), 「＋ 새 폴더」 버튼, 위 막대 메뉴 묶기, **폰 폭(≤560px)에서 홈을 위아래로 쌓기**(전엔 목록과 입력창이 옆으로 눌려 글자가 세로로 부서짐)
- `test/folders.test.js`(새 파일) — 8건

## 7. 남은 문제
- 폴더 안의 폴더(중첩)는 없습니다. 한 단계만.
- 캠페인 id 가 이름에서 나와(같은 이름이면 같은 id) 폴더 배정도 같은 이름끼리 공유됩니다 — 기존 저장 방식의 한계.
- 이미 썸네일이 만들어진 뒤 썸네일 규칙(여백 등)을 바꾸면 로고가 바뀌기 전까지 옛 썸네일이 남습니다. 바꿀 일이 생기면 `logoThumb` 에 판 번호를 더할 것.
- 위 막대 메뉴의 유리 팝오버는 뒤 목록 글자가 비쳐 보입니다(기존 스타일).
