# 2026-10-21 읽은 내용 카드 — 자유 입력창 삭제, 필수 4칸 입력 카드

## 발단
사용자가 대화 화면 하단의 자유 입력창(「답장을 입력하세요…」 + 「+」 첨부)을 가리키며 「이거도 자연어 입력영역 없어도 되는 거 아님?」. 입력창이 하던 일 세 가지를 따져 보니 전부 카드로 대체할 수 있었다.

| 입력창이 하던 일 | 대체 |
|---|---|
| 빠진 필수값 묻기(고객사·채용 구분·직무 없으면 「○○이 뭐예요?」 → 말로 답) | 읽은 내용 카드의 빈 칸(빨간 테두리) |
| 「고칠 게 있으면 아래 입력창에 말로」 수정 | 같은 카드에서 직접 고침 |
| 「+」 키비주얼·로고 첨부 | 스타일 카드의 키비주얼·로고·흰 로고·누끼 썸네일과 중복 |
| 자유 글 명령(「다크로」「#hex」「에브리타임 빼」) | 매체 카드·스타일 카드에 다 있음 |

사용자 결정: **입력창 지우고 「읽은 내용」을 필수 4칸 입력 카드로**.

## 바꾼 것
1. **입력창 삭제** `app/index.html` — `.composer`(답장 입력·보내기·+ 첨부) 마크업·CSS 제거, `#slot` 만 남김. `app/app.js` 의 `cvGo/cvIn/cvFile` 핸들러, `answerAsk`, `it.asking` 상태, `turn()` 의 묻는 분기 삭제. `turn()` 은 이제 홈 브리프 한 번(초기 해석)에만 쓰인다.
2. **단계** `stepOf`: `ask` → `brief`. 어디에를 고르면 `afterWhere()` 가 「브리프에서 이렇게 읽었어요. 맞으면 다음, 다르면 칸에서 바로 고치세요」(못 읽은 필수값이 있으면 「○○은 못 읽었으니 채워 주세요」)를 말하고 `slotBrief()` 카드를 띄운다.
3. **읽은 내용 카드** `slotBrief()` — 필수 칸 격자(채용: 고객사·채용 구분·모집 직무·지원 마감 / 행사: 행사명) + 접힌 「선택 항목 6개 · n개 읽음」(접수 시작·시즌·슬로건·고지·고용 형태·근무지 — 마감 시각 칸은 사용자 「필요 없을 것 같음」으로 뺐다, 파서가 읽으면 날짜 뒤에 붙는 건 그대로; 읽은 값이 있으면 펼쳐진 채). 빈 필수 칸은 `.miss`(빨간 테두리), 상태 줄에 「고객사 필요」. 날짜 칸은 떠날 때 `normDate` 로 YYYY-MM-DD(「10.31」→ 2026-10-31). Enter = 다음. 「이전」은 어디에 카드로.
4. **「다음」을 막는 건 ESSENTIAL(고객사·채용 구분·직무)뿐** — 마감은 필수 표시(*)만 하고 비워 둘 수 있다(한진처럼 「공고별 상이」인 공고). 비우면 상태 줄 「마감 없이 진행 — 지면에 날짜 줄이 빠져요」. 다음을 누르면 읽은 한 줄(`readLine`: 「2026년도 · 한진정보통신 · 경력직 · SW개발, 보안 · 10.31(토) 마감」)이 사용자 말풍선으로 남고 스타일로.
5. 카드 CSS `.bf`(2열, 560px 아래 1열) · `.bmore`(details) — 기존 `.f label/.req/input/.miss` 재사용.

## 확인
- 테스트 538 통과(`node --test`). `agent.test.js` 의 `ESSENTIAL/ASK` 단언은 그대로(ASK 문구는 앱에서 더 안 쓰지만 모듈에 남김).
- 브라우저(localhost:4795): 한진 샘플 → 광고 소재 → 매체 4 → 카드에 고객사·채용 구분·직무·시즌·고지 읽힘, 마감 빈 칸 안내. 고객사를 지우면 빨간 칸 + 「고객사 필요」, 다음 누르면 토스트 「고객사를 채워 주세요」로 막힘. 마감 「10.31」 입력 후 포커스 떠나면 2026-10-31. 다음 → 「… 10.31(토) 마감」 말풍선 → 스타일 카드.

## 남은 것
- AI 해석(`agentTurn`)은 홈 브리프 첫 해석에만 남았다. 키 없으면 규칙 파서. 대화 수정 경로가 없어졌으니 결과 화면의 일괄 편집(인스펙터)이 유일한 사후 수정.
- 행사 트랙은 행사명만 필수 — 일시·장소는 선택 칸.
