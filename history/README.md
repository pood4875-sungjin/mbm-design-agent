## 쌓는 규칙 (Claude용)
- 작업을 마치면 다음 세 가지를 합니다.
  1. 날짜별 기록을 새로 만듭니다.
  2. 위 표에 한 줄을 추가합니다.
  3. `00_브리핑.md`의 「지금 어디」「정해야 할 것」「테스트 누적」을 갱신합니다.
- 한국어로, 쉽게 씁니다. 규칙을 바꿨으면 `파일:줄 · 이전 → 이후 · 근거 케이스`를 남깁니다.
- **규칙을 넣거나 바꾸면 `ref/learned/rules.json` 에 한 줄 추가·수정하고 `node scripts/rules-ledger.mjs --md` 로 검사합니다**(규칙장부.md 표가 같이 갱신됩니다) 앱 「가이드 검수」 문장을 맞추려면 `node scripts/build-rules.mjs` 로 `core/rules-data.js` 도 다시 만듭니다(10-14).
- 테스트 수치는 `ref/learned/cases/rounds.json`(라운드 기록)에서 옮깁니다. 추측으로 채우지 않습니다.
- 이미지는 `ref/learned/cases/_out/`에 있습니다. 이 폴더는 git에 올라가지 않는 로컬 전용입니다. 링크는 상대경로로 겁니다.
- 사용자 결정이 나면 브리핑의 「정해야 할 것」에서 지우고, 날짜별 기록에 「결정: …」으로 남깁니다.

## 가이드 대조표 읽는 법
`ref/learned/cases/_out/trace/index.html`(케이스마다 `trace/<id>.html`). 만드는 법: `node scripts/guide-trace.mjs [id …]` 또는 `node scripts/cases.mjs run --trace`. 보는 법: `python3 scripts/serve.py 4792` → http://localhost:4792/ref/learned/cases/_out/trace/index.html
- 케이스마다 대표 4규격(가로형 580×400 · 가로 띠 1005×360 · 세로형 300×600 · 정사각 1080) + 자동 검수 경고가 난 규격을 다시 그려, 왼쪽에 그림, 오른쪽에 규칙 표를 둡니다.
- 표의 한 줄 = 규칙 하나. 「가이드 값」은 `ref/learned/rules.json`(규칙 장부)·`core/canon.js`·`core/kvtypes.js`·매체 guide 에서 읽은 기대값, 「실제」는 headless Chrome 의 DOM 실측(글자 px·굵기·자간·로고 상자·마스크 녹임 길이·스크림 불투명 + KV 알파를 캔버스로 읽은 보이는 면적·잘린 변)입니다.
  - 예) 「단일 사물 누끼 면적: 22~27% → 실제 24% ✓」「블리드 잘림: 오른·아래 ≤ 30% → 오른 18% · 아래 12% ✓」「녹임 길이: 거리별 필요 ≥ 45% → 22% ✗」「굵기: 메인 700 → 700 ✓」.
- **✓** 숫자가 맞음 · **✗** 어긋남 — 「가이드는 X 라는데 렌더는 Y」: 렌더러 틈이거나, 가이드 문장이 코드보다 느슨한 것(그러면 rules.json 문장을 고친다) · **–** 해당 없음 또는 측정 불가(사람이 봐야 하는 규칙 — 유형 판정이 맞는가·이음매가 눈에 띄는가·AI 티·얼굴 옆 글자·로고 가독·지면 분위기·위계·누끼 선택). – 를 ✓ 로 치지 않습니다.
- 「✗ 규칙별 모음」(index 아래쪽)이 규칙 수정 후보 목록입니다. 규칙 문장·판정 논리만 고쳤으면 `--reeval`(렌더 없이 다시 판정). 「렌더 추적(data-trace)」을 펼치면 렌더러가 내린 결정(유형·배치 모드·지면 출처·스크림·로고·글자 크기·걸린 규칙 이름)과 실측 JSON 이 그대로 보입니다.
