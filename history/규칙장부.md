# 규칙 장부 — 디자인 규칙이 다 어디 있나

> 마지막 갱신: 2026-10-14(테스트 예시 1014 +13) · 기계용 원본은 `ref/learned/rules.json`(한 규칙 = 한 줄). 아래 표는 `node scripts/rules-ledger.mjs --md` 가 거기서 만든다.

검증 라운드를 돌 때마다 규칙이 하나씩 늘었는데, 그게 코드 여기저기에 흩어져 「어디로 들어갔는지」 보이지 않았다. 이 장부는 그 규칙을 **한 줄에 하나씩** 모은 것이다. 10-06 이후 검증에서 나온 규칙과, 그전부터 있던 기본 규칙(「10-06 이전」)을 함께 적었다.

## 어떻게 작동하나 (코드 모르는 디자이너용)

### 1. 그림을 올리면 일어나는 일 — 순서대로

1. **측정** — 그림을 픽셀로 잰다. 네 변이 평평한지(한 색인지), 바탕이 투명한지, 전체가 밝은지 어두운지, 색이 얼마나 넓게 퍼졌는지, 날카로운 경계가 얼마나 있는지, 그리고 「주인공」(바탕과 다른 덩어리)이 어디에 얼마나 큰지. 로고도 같이 잰다(바탕을 지우고 여백을 자르고 밝기·대표색).
   → 이 단계의 규칙은 **「누끼·로고 손질」** 묶음과 「유형 판정」의 측정 문턱에 있다.
2. **유형 판정 — 질문 4개** — ① 바탕이 투명한가? → 누끼. ② 평평한 변이 하나도 없는가? → 사진. ③ 평평한 변이 있는가? → 배경 있는 일러스트·3D. ④ 경계 없이 매끈한가? → 질감.
   → **「유형 판정」** 묶음.
3. **세부 유형** — 누끼면 캐릭터인지 사물인지 떼인지 유리인지 장식 프레임인지, 사진이면 인물·군중·어두움·밝음·여백, 일러스트면 캐릭터·그라데이션 바탕·배경형·오브젝트·장면, 질감이면 어둡고 밝음. 측정값으로 가른다.
   → **「유형 판정」** 묶음(세부 유형 깃발).
4. **매체 규정으로 틀 잡기** — 74개 규격마다 매체가 정한 크기·글자 수·글자 크기 범위·로고 유무·오브젝트 자리를 먼저 깐다. 템플릿을 실측한 매체(자소설·에브리타임·구글 가이드)는 그 값도 여기서.
   → **「매체 규정」** 묶음.
5. **유형 규칙·공통 규칙으로 배치·지면·글자 결정** — 그림을 어디에 얼마나 크게(배치·비중), 어느 변을 얼마나 잘라도 되는지(자르기·블리드), 남은 지면은 무슨 색인지(지면 색), 그 위 글자는 무슨 색이고 가림막이 필요한지(글자 색·스크림), 그림과 지면을 어떻게 잇는지(이음·녹임), 문구를 어떤 크기·굵기·줄바꿈으로 앉히는지(타이포), 로고는 어디에 얼마나 어떤 색으로(로고).
   → **「배치·비중」「자르기·블리드」「지면 색」「글자 색·스크림」「이음·녹임」「타이포」「로고」** 묶음.
6. **그리기** — 위에서 정한 대로 74규격을 그린다.
7. **자동 검사 2종** — ① 규격 검사: 치수·용량·글자 수가 매체 규정에 맞는가. ② 디자인 검사: 글자가 주인공 위에 올라갔나, 주인공이 로고를 가렸나, 그림이 뚝 끊겼나, 빈 띠가 크나, 글자가 잘렸나, 녹임이 짧나, 질감 위 글자가 어지럽나. 그림 탓(작은 원본)은 「참고」로 따로 센다.
   → **「자동 검사」** 묶음.
8. **승인** — 디자이너가 보고 내보낸다. 자동 검사가 못 보는 것은 사람 판정 시트로 모은다.

### 2. 규칙끼리 부딪히면 누가 이기나

**매체 규정 › 매체 템플릿 실측 › 매체 가이드 › 공통 규칙 › 기본 형태 문법** 순이다.

예: 자소설 채용공고의 13px 흰 글자. 공통 규칙은 「어두운 지면 위 14px 미만 글자는 Medium 이상」이지만, 자소설 템플릿 실측이 Regular(400)라 400으로 나간다. 반대로 유리 누끼의 「어두운 지면 먼저」는 공통 규칙이 구글 가이드의 「밝은 지면」을 이기는 예외인데, 그래도 매체 **규정**(자소설 형광·분할 배경 금지, 리멤버 검정 금지)은 넘지 못한다.

### 3. 규칙은 어떻게 생기나

케이스 테스트(그림 92장 × 74규격) → 깨진 곳 발견(자동 검사 경고 또는 사용자·디자이너 눈) → 원인 가르기(**규칙 탓 / 그림 탓 / 오탐**) → 규칙 탓이면 규칙 추가·수정 → 전 케이스 다시 돌려 회귀 확인(이전 라운드와 규격·문장까지 비교) → 테스트 추가 → **이 장부에 한 줄**.

정책: **근거가 1건이어도 일단 넣는다.** 다른 케이스와 부딪히면 조정하고, 깔끔히 안 풀리면 그 규칙만 되돌리고 기록한다. 그래서 「근거가 1건뿐인 규칙」 절을 따로 둔다 — 반대 사례가 나오면 먼저 의심할 곳이다.

### 4. 규칙이 사는 세 곳

| 어디 | 무엇 | 예 |
|---|---|---|
| **숫자 규칙** | 「얼마나」를 정한 수치. 한 파일에 이름 붙여 모아 둔다 | 녹임 길이 30~55%, 누끼 확대 상한 1.5배, 로고 폭 ≤ 메인 글자 × 2.4 |
| **분기 규칙** | 「이런 그림이면 이렇게」라는 갈래. 유형·세부 유형 판정과 그에 따른 배치 | 「군중 사진이면 지면 전체에 깔고 브랜드색을 덮는다」, 「캐릭터 누끼는 머리를 자르지 않는다」 |
| **매체별 예외** | 매체 하나에만 적용되는 값. 공통 규칙 위에 덮는다 | 에브리타임 메인 ExtraBold, 카카오 글자 48~164px, 자소설 자간 0 |

### 5. 판정이 틀렸을 때 디자이너가 할 수 있는 것

앱의 **「키비주얼 유형」** 선택 상자(그래픽 가이드 단계와 인스펙터 「스타일」 맨 위)에서 유형이나 세부 유형을 직접 고른다. 기본은 「자동(지금: …)」이다. 예: 흰 가운 의사 사진이 「일러스트」로 잡혔으면 「인물 사진」을 고른다 — 배치·지면·글자 규칙이 함께 따라온다. 그림을 바꾸면 다시 「자동」으로 돌아간다.

### 규칙 하나 넣는 법 (Claude·사람 공통)

1. 코드의 데이터 자리에 값을 넣는다(숫자는 공통 기준 파일, 분기는 유형 파일·렌더러, 매체 값은 매체 JSON).
2. `ref/learned/rules.json` 에 한 줄 추가(id·묶음·쉬운 한 문장·수치·근거 케이스·날짜·라운드·코드 위치·출처 기록).
3. `node scripts/rules-ledger.mjs --md` — 형식·id 중복·파일 존재를 검사하고 이 문서의 표를 다시 만든다.
4. 날짜별 히스토리 기록에 `파일:줄 · 이전 → 이후 · 근거` 를 남긴다.

표 읽는 법: **규칙 id** 뒤 문장이 규칙, *(근거 1건)* 과 **(되돌림)** 은 상태. 「들어온 날 (라운드)」의 r 번호는 `ref/learned/cases/rounds.json` 의 라운드다.
