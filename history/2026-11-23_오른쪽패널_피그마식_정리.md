## 1. 카카오 비즈보드(960×300) 광고주체 로고가 그림 밖으로 어긋남
- 증상: 로고가 썸네일 왼쪽 위 밖에 반쯤 걸쳐 있었다(사용자 캡처: 그림 x 662 · 폭 259, 로고 x 609).
- 원인
  - 썸네일 칸을 덮어 채울 때 주인공이 60%보다 적게 보이면 칸을 그림 크기로 줄여 오른쪽에 붙이는 규칙(`slotFit`)이 있다.
  - 이 규칙이 공식 크기 고정 칸(둥근 320×222)에도 걸렸다. 그림은 260 폭으로 줄었는데 광고주체 로고는 원래 칸(601+8) 기준이라 어긋났다.
  - 11-15 결정 「공식 칸은 줄이지 않는다」에도 어긋난다.
- 고침: 둥근 공식 칸(`roundSlot`)은 `slotFit` 을 건너뛴다(core/renderers/ad.js). 재현 입력(ar 1·0.8)에서 칸 601·320×222, 로고 609.

## 2. 오른쪽 패널 피그마식 정리(사용자 「불필요한 거 없애고 피그마 편집기같이」, 정리안 선택)
- **이 소재만**
  - 순서: 레이아웃 안 → 채우기 → 키비주얼 → 글자 → 선택 색 → 요소 → 고급.
  - **채우기**(새): 이 소재 배경을 지면 줄 + 층으로 편집한다(`a.overrides.style.background`).
    - 예전 「배경」 프리셋(배경·그라데이션 버튼)과 배경색 한 줄을 대신한다.
    - 「로컬 앱에서 배경 컬러 편집이 안 된다」던 곳이다. 앱에서 지면 색을 바꾸면 그 소재 배경이 바로 바뀌는 것을 확인했다.
  - 키비주얼 위치·크기·스크림: 버튼 줄 + 설명 → 이름 + 드롭다운 한 줄(`presetArtifactHtml compact`). 못 고르는 값은 비활성 + 이유.
  - 글자: 폰트 + 칠(한 줄, 비면 「자동」) + 정렬. 글자색 공통/흰/검정 세그먼트와 「글자별 편집」을 뺐다. 글자마다는 캔버스에서 글자를 골라 요소 패널에서 고친다.
  - 선택 색: 주·보조·포인트 칩 한 줄.
  - 고급(접힘): 글자 세로 위치 · 정보 태그 · 태그 모양 · 가이드.
- **전체 일괄**
  - 순서: 페이지 → 배경(채우기) → 키비주얼 → 로고 → 글자 → 선택 색 → 내보내기 → 도구 → 고급.
  - 글자: 폰트 줄 + 폰트 파일 첨부 링크 + 칠 + 정렬. 기본/흰/검정 세그먼트와 긴 설명을 뺐다.
  - 고급(접힘): 글자 세로 위치.

## 4. 캔버스 그라데이션 방향 손잡이(채우기 2차, 사용자 「fill 누르면 프레임에서 방향 설정 — 피그마처럼」)
- 그라데이션 칠의 팝업을 열면 칠한 상자 위에 손잡이가 뜬다(app/fillpanel.js drawHandles).
  - 대상 상자: 이 소재만 배경 = 그 소재, 전체 일괄 배경 = 고른(없으면 보이는 첫) 소재, 글자·상자 칠 = 그 요소.
  - 선형: 시작·끝 손잡이 + 선 + 가운데 정지점 점. 끌면 각도와 선 위 자리(from·to %)가 바뀌고, Shift 를 누르면 45° 단위.
  - 방사형: 중심 · 가로 반지름 · 세로 반지름 손잡이 + 타원. Shift 를 누르면 원.
  - 캔버스를 옮기거나 확대해도 매 프레임 자리를 맞춘다. 끄는 동안은 보드 미리보기, 놓으면 한 번 저장.
- 값(core/gradient.js normGradient)
  - 선형 from·to: CSS 그라데이션 선 위 % — 정지점 위치를 from~to 로 옮겨 그린다. 손잡이를 선에 수직으로 옮긴 것은 같은 그림이라 선 위로 투영한다.
  - 방사형 cx·cy·rx·ry: `radial-gradient(ellipse rx% ry% at cx% cy%)`. 값이 없으면 예전 「가운데 원」 그대로다.
- 확인

## 6. 레이아웃 안 모달 · Shift 다중 선택 · 커서/손 도구 분리
- **레이아웃 안**(사용자 「나열하지 말고 다른 시안 보기 버튼만 — 모달에서 눌러 변경」)
  - 패널에는 지금 안 한 줄(번호 · 이름 · 설명) + 「다른 시안 보기」 + 「이 안으로 전부」만 둔다.
  - 모달은 레이아웃 안 4개 + 다른 시안(틀·내 자유 시안)을 함께 보여 주고, 같은 틀은 한 번만 나온다. 카드를 누르면 바로 바뀐다.
  - 패널 썸네일 iframe 을 매번 그리지 않아 소재를 고를 때도 가벼워졌다.
- **Shift 다중 선택**(app/elselect.js)
  - 요소를 고른 뒤 Shift+클릭(캔버스 · 요소 목록)으로 같은 소재의 요소를 더하거나 뺀다.
  - 하나를 끌면 모두 같은 만큼 움직인다. 놓을 때 저장은 한 번이다(되돌리기 한 걸음, 밖으로 나간 것은 안쪽으로).
  - 화살표 키도 함께 움직인다. 위치 고정 규격의 글자는 빠진다.
  - 패널에 「N개 선택 — …」 한 줄을 보인다.
- **커서(이동 V) / 손(H) 도구**(사용자 「커서일 땐 장면 이동이 아니라 드래그로 여러 개 선택」)
  - 커서: 고른 소재 안에서 끌면 선택 상자에 걸친 요소들을 고른다. 빈 캔버스·다른 소재에서 끌면 소재들을 고른다(「선택하기」 상자). 끌지 않은 클릭은 예전처럼 고르기·해제다.
  - 화면 이동: 손 도구 · Space 누른 채 · 가운데 버튼 · 휠.
- 확인(로컬 앱, 실제 마우스)
  - 고른 소재 위를 끌자 요소 4개가 선택됐다. 함께 끌자 메인·날짜·키비주얼이 같은 만큼(+74, −25) 움직였다.
  - 빈 곳을 끌자 화면은 그대로 두고 소재 4장이 선택됐다. 손 도구에서는 화면이 이동했다.
  - Shift+클릭으로 키비주얼이 더해졌다. 콘솔 오류는 없었다.
- 테스트: npm test 966개 중 904 통과, 실패 62(이전과 같은 목록). 다중 선택·도구는 브라우저 동작이라 자동 테스트가 없다.
- 덧: 왼쪽 「서브 문구」 칸에 기본값 보이기(사용자 「서브 문구에 디폴트로 써져 있는 것 넣어 줘야」)
  - 예전(11-10): 서브는 자동 없음이라 비워 두면 칸도 비어 있었다. 그런데 매체가 넣는 서브(고객사·시즌 등)는 소재에 찍혀 있었다.
  - 이제 메인·날짜처럼 지금 소재에 가장 많이 찍힌 서브 글자를 칸에 보이고 「자동」 표시를 단다. 그대로 두고 반영하면 고정하지 않는다(예전과 같은 규칙).
  - 서브가 찍힌 소재가 없는 캠페인은 빈칸 + 「자동」.

## 7. 커서 모양 · 휠 이동 · 다른 소재끼리 Shift 선택(사용자 「피그마랑 같아야 — 모양도 커서」, 피그마 캡처)
- **커서 모양**
  - 캔버스 기본 커서가 손(grab)이었다. 이제 커서 도구 = 화살표(소재·선택 상자 위도 화살표, 모서리만 크기 화살표)다.
  - 손 도구(H) · Space 누른 동안 = 손, 끄는 중 = 쥔 손.
  - 손 도구는 예전 그대로(끌면 화면 이동, 소재 클릭 안 받음)다.
- **휠·트랙패드**: 두 손가락 스크롤·마우스 휠 = 그 방향으로 화면 이동(Shift+휠 = 가로), 핀치·⌘/Ctrl+휠 = 확대·축소. 예전에는 휠이 확대·축소뿐이었다.
- **Space**: 커서 도구에서 누르는 동안 잠깐 손 도구다(떼면 커서). 확인했다.
- **다른 소재끼리 Shift 선택**
  - 요소를 고른 채 다른 소재의 요소를 Shift+클릭하면 함께 고른다.
  - 소재마다 선택 상자와 크기 표시(예: 274 × 400 · 349 × 177)가 뜬다.
  - 끌면 모두 화면에서 같은 거리만큼 움직인다(소재마다 보드 배율이 달라 소재 안 px 은 다를 수 있다). 저장은 되돌리기 한 걸음(elCommitMany)이다.
  - 패널에 「N개 선택 — 소재 이름 요소」가 보인다.
- 확인: 로컬 앱(실제 마우스 끌기)에서 두 소재의 키비주얼이 함께 움직였다. 콘솔 오류는 없었다.
- 테스트: npm test 966개 중 904 통과, 실패 62(이전과 같은 목록).

## 8. 끊김 · 손 도구 선택 상자 · 피그마식 끌기 선택(사용자 「전환되는 과정에서 랙」, 「더 크게 잡으면 프레임도 선택」)
- **끊김**
  - 선택 상자를 끄는 동안 움직일 때마다 카드 47장의 자리를 다시 재고 전부 다시 칠했다.
  - 이제 카드 자리는 끌기 시작할 때 한 번만 잰다. 판정은 한 프레임에 한 번, 바뀐 때만 칠한다(app/select.js · 새 선택 상자).
- **손 도구인데 보라 상자가 남던 것**
  - 끌기로 소재를 고르면 「선택하기」 모드가 켜진 채 남았다. 그 상태에서 손으로 끌어도 선택 상자가 먼저 잡혔다.
  - 이제 손 도구 · Space · 가운데 버튼은 언제나 화면 이동이다. 손으로 바꾸면 끌던 상자를 끝낸다.
- **피그마식 끌기 선택(커서 도구 하나로)**
  - 상자에 다 들어간 소재 = 소재째 선택(끄는 동안 파랑 테두리로 미리 보인다).
  - 일부만 걸친 소재 = 상자에 걸친 요소(글자·로고·키비주얼)를 선택한다.
  - 작게 잡으면 요소, 크게 잡으면 소재까지 잡힌다. 빈 캔버스에서 시작해도 소재 위에서 시작해도 같다.
  - 새로 끌면 선택을 바꾸고, Shift+끌기는 더한다. 소재를 그냥 누르면 「선택하기」 모드를 끝내고 일반 선택이다(Shift+누르기는 더하기).
  - 상자 색을 피그마 파랑으로 바꿨다.
- 확인(로컬 앱, 실제 마우스)
  - 큰 상자: 970×250 소재째 + 300×600 요소 4개.
  - 이어서 작은 상자: 이전 선택이 풀리고 580×400 의 메인 문구 · 키비주얼.
  - 콘솔 오류는 없었다.
- 테스트: npm test 966개 중 904 통과, 실패 62(이전과 같은 목록).
- 덧: 왼쪽 메인·서브·날짜 칸이 비어 보이던 것(사용자 「왜 패널에 문구들 삭제됨」)
  - 원인: 칸의 자동 문구는 그려진 소재에서 읽어 채운다(leftLiveRefresh). 그런데 왼쪽 칸에 포커스가 있으면 「입력 중」으로 보고 다시 채우지 않았다. 소재 47장이 다 그려지기 전에 칸을 누르면 빈 칸으로 멈췄다(저장값은 그대로, 보이는 칸만 빔).
  - 고침: 손대지 않은 자동 칸(값 = 자동값)은 포커스가 있어도 그 자리에서 값만 채운다. 사람이 고친 칸은 건드리지 않는다.
  - 확인: 캠페인을 열자마자 메인 칸을 누른 상태로 재현했다. 처음에는 빈 칸이었고, 그려진 뒤 메인 「AK PLAZA 경력 채용」 · 날짜 「11.18(수) - 12.2(수)」가 채워졌다.
  - 예전부터 있던 문제다(공개 주소에도 있음).
